# Как подключить готовую PostgreSQL-базу к Android-приложению

## Коротко

Android-приложение **не должно подключаться к PostgreSQL напрямую** через логин/пароль от базы. Правильная схема для диплома:

```text
Android-приложение → REST API на сервере/ноутбуке → PostgreSQL
```

Так безопаснее и проще защищать диплом: пароль от PostgreSQL остается на сервере, а приложение отправляет обычные HTTP-запросы.

## Почему не подключаем PostgreSQL прямо из приложения

1. Логин и пароль от базы попадут внутрь APK, их можно вытащить.
2. PostgreSQL-порт придется открывать в сеть.
3. JDBC-драйверы для Android часто работают нестабильно или требуют лишних зависимостей.
4. В реальных проектах мобильные приложения ходят в backend API, а не напрямую в БД.

## Что нужно сделать с готовой базой

### 1. Проверить таблицу пользователей

Если таблицы пользователей еще нет, можно создать такую:

```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    full_name TEXT NOT NULL,
    email TEXT NOT NULL UNIQUE,
    password_hash TEXT NOT NULL,
    password_salt TEXT NOT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

Если таблица уже есть, нужно просто сопоставить ее поля с формой регистрации в приложении:

| Поле в приложении | Поле в PostgreSQL |
| --- | --- |
| ФИО | `full_name` |
| Email | `email` |
| Хэш пароля | `password_hash` |
| Соль пароля | `password_salt` |
| Дата регистрации | `created_at` |

### 2. Сделать маленький backend

Можно сделать backend на любом стеке: Spring Boot, Ktor, Node.js, FastAPI, PHP. Для диплома достаточно двух endpoint-ов:

```text
POST /api/register       — регистрация пользователя
GET  /api/users          — список пользователей для демонстрации
```

Пример JSON, который Android будет отправлять на регистрацию:

```json
{
  "fullName": "Иван Иванов",
  "email": "ivan@example.com",
  "password": "123456"
}
```

Пример успешного ответа:

```json
{
  "id": 1,
  "fullName": "Иван Иванов",
  "email": "ivan@example.com",
  "createdAt": "2026-06-04T12:30:00"
}
```

Важно: хэшировать пароль лучше на backend-е, а не в Android-приложении. Тогда Android отправляет пароль по HTTP(S), backend считает хэш и сохраняет результат в PostgreSQL.

### 3. Подключить Android к backend API

В Android-коде текущий `UserRepository` сейчас работает как локальная демонстрационная база через Room. Для PostgreSQL нужно заменить его реализацию на сетевую:

```kotlin
class UserRepository(
    private val api: UserApi
) {
    suspend fun registerUser(fullName: String, email: String, password: String) =
        api.register(RegisterRequest(fullName, email, password))

    suspend fun getAllUsers() = api.getUsers()
}
```

То есть экран регистрации можно оставить почти таким же, но вместо локального Room-репозитория вызвать API.

## Какие данные нужны, чтобы подключить именно вашу базу

Чтобы настроить проект под вашу готовую PostgreSQL-базу, нужны:

1. Адрес сервера PostgreSQL: например `localhost`, IP или домен.
2. Порт: обычно `5432`.
3. Название базы.
4. Название таблицы пользователей.
5. Названия колонок для ФИО, email и пароля.
6. На чем удобнее сделать backend: Spring Boot, Node.js, FastAPI, PHP или другое.

## Если backend запускается на вашем ноутбуке

Для Android-эмулятора адрес компьютера обычно такой:

```text
http://10.0.2.2:8080
```

Для реального телефона нужно, чтобы телефон и ноутбук были в одной Wi‑Fi сети, а в приложении указывается IP ноутбука, например:

```text
http://192.168.1.10:8080
```

## Что показывать в дипломе

Можно объяснить так:

> Мобильное приложение отправляет данные регистрации на серверное API. Сервер проверяет данные, хэширует пароль и сохраняет пользователя в PostgreSQL. Такой подход безопаснее прямого подключения мобильного приложения к базе данных, потому что реквизиты доступа к PostgreSQL не хранятся внутри APK.
